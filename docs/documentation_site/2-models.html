All models at a glance

The system is a cascade. One general object detection model looks at every frame and finds vehicles and people. Small specialist models then look only at the crops they need (a rider, a plate, a windshield). A tracker keeps one steady number on each vehicle, and a text reader turns the plate crop into letters. Everything that is not a picture model (the rules that decide a violation) is explained on page 4.

Model 1 · first stage, every frame

Vehicle detector

Job. Look at the whole camera frame and draw a box around every vehicle and every person. Everything later (tracking, zones, riders, plates) starts from these boxes.

Active file
yolo11_primary.onnx · chosen in the dashboard Models tab and stored in models/active_model.txt
Other files
yolov8n.onnx (Ultralytics' own release of the pretrained nano model, fetched by scripts/download_model.py) and yolo26_primary.onnx (kept for comparison)
Where it comes from
Stock pretrained YOLO models trained by Ultralytics on COCO. The yolo11 and yolo26 files were exported to ONNX with Ultralytics 8.4.160 (read from the files' own metadata); the exact source weights and who exported them are not recorded in the repository.
Starting model
None: we use it as downloaded. We have not fine-tuned a deployed vehicle model.
Input
One picture, letterboxed to 640 x 640, RGB, values 0 to 1.
Output
8,400 candidate boxes with 80 class scores each; boxes under confidence 0.45 are dropped, duplicates are removed by NMS (overlap above 0.50). People get their own NMS group so a rider does not delete the motorcycle.
Classes we keep
From COCO's 80: person, bicycle, motorcycle, car, bus, truck, traffic light, stop sign. Everything else is ignored.
Not in COCO
Tricycle and jeepney. They appear as motorcycle, car, bus or truck, or are missed.
The Philippine fine-tune that exists but is not deployed

A 6-class run (motorcycle, car, bus, truck, person, tricycle; jeepney as bus) started from yolov8n.pt on the vehicle set and was planned for 30 epochs. It stopped at epoch 23 with mAP@50 0.68, below the 0.80 target, and was never deployed. Continue it (Training Studio → Continue) and test it on the local clip before switching.

How the specialist models are fed

All three specialists are run through the same two functions. This matters: the models were trained by Ultralytics on RGB pictures that were letterboxed, and their duplicate boxes were removed with NMS. An earlier version of the app fed them BGR, stretched crops and no NMS, and on held-out photos the plate was found 7% of the time instead of 85%. The fix lives in one file so it cannot drift.

Model 5 · same number for the same car

Trackers and the car matcher

Job. Give every vehicle one steady track ID from frame to frame, even when it is briefly hidden. Violations that depend on movement (counterflow, parking, turns) need this.

DeepSORT
Predicts where a vehicle should be next and also compares what it looks like using a small network (the car matcher). The system uses it as the default for forensic analysis. Settings: forget a vehicle after 60 missed frames, 3 confirmed frames before an ID is locked, appearance distance limit 0.4.
ByteTrack
Matches only by box overlap. Faster, but in one check on our footage it left 58% of detections without a track (DeepSORT: 2%). It is the analysis wizard's default, so choose DeepSORT. Settings: 60 missed frames, matching threshold 0.2.
Car matcher network
ckpt.t7 (46 MB). It is the original network shipped with DeepSORT, a small CNN trained on Market-1501, a dataset of pedestrians; it reads a 64 x 128 picture and returns a fingerprint. It has not been replaced.
Starting point for our own
The fine-tuning script starts from the current ckpt.t7, keeps its classifier layer so DeepSORT loads it with no code change, and deploys a new file only if it finds unseen cars better (page 3).
Evidence it can improve
On 67 real ticketed cars from two clips, the fine-tuned matcher found a car again 85.3% of the time versus 76.7% for the stock one, on new cars from the same cameras (3 of 3 random splits); on a different road there was no gain.
Locked
The tracker settings are locked by the project owner: do not tune them. If tracking must improve, replace or fine-tune the matcher.

Model 6 · from plate picture to plate text

Plate reader (OCR) and picture enhancers

Job. Turn a cropped plate picture into letters and digits. The plate model finds the plate; this step reads it. Each vehicle keeps up to 40 plate crops, every crop is read, and the most voted reading wins, so one blurry frame cannot decide the plate.

Reader
EasyOCR for English. It finds the text in the crop and reads each piece. It is restricted to the characters 0-9 and A-Z. Its network files are downloaded by the library on first use (not stored in this repository). PaddleOCR can be chosen instead if it is installed.
Not trained by us
The EasyOCR package has no trainer, so the plate text set can only score it. A PaddleOCR trainer is written but its tools are not installed.
Format rule
ph_standard assumes 3 letters then 4 digits and fixes look-alikes by position (for example an O in a digit place becomes 0). uk_standard and raw also exist. Set plate_format to ph_standard for local demos.
Enhancers (before reading)
Lanczos (classic, default): enlarge 4 times smoothly. LapSRN x8: a small network (LapSRN_x8.pb, 3.9 MB, from an open TensorFlow port, run through OpenCV) that enlarges 8 times. Real-ESRGAN: a GAN that enlarges 4 times (realesrgan.onnx, 67 MB, the size of the official x4plus model; the repository does not record which of its two scripts made the deployed file).
Honest note
Enhancers can invent plausible but wrong characters. They are optional, and a read is kept only as one vote among many.

Terms used on this page

On screen, hover or tab to any dotted word for its meaning. This list is the same meanings, for the printed copy.

AMP
Automatic mixed precision: training with smaller numbers where safe, which is faster and uses less memory.
batch
The number of pictures the model looks at together before it adjusts itself once.
ByteTrack
A tracker that matches objects between frames only by how much their boxes overlap. Fast, but it ignores looks.
cascade
Steps in a line: one general detector first, then specialist models only on the crops that need them.
COCO
A famous public photo collection with 80 everyday object kinds (person, car, bus, truck...). Many models start from it.
confidence
The model's own certainty for one detection, from 0 to 1.
DeepSORT
A tracker that matches objects between frames using where they should be (motion) and what they look like (a fingerprint).
early stopping
Stopping training when the score has not improved for a set number of epochs (called patience).
EasyOCR
A free OCR library. We use it to read the characters of a cropped licence plate.
fine-tuning
Training a pretrained model a little more on our own pictures so it learns our task.
fingerprint
A short list of numbers a network computes from a picture. Pictures of the same car should give close numbers.
fitness
The score Ultralytics uses to choose the best saved epoch: 10% of mAP@50 plus 90% of mAP@50-95.
GAN
Generative Adversarial Network: two networks compete, one draws images and one judges them, until the drawn images look real.
HSV
A way to describe colour as hue (which colour), saturation (how strong) and value (how bright). Good for finding red, amber or green.
Hz
Times per second. A light that blinks at 1 Hz switches on and off once every second.
image size
The square size in pixels (for example 640 x 640) that pictures are resized to before the model sees them.
Lanczos
A classic, non-AI way to enlarge a picture smoothly.
LapSRN
A super-resolution network that enlarges a picture step by step. We use its 8-times version.
learning rate
How big each adjustment step is. Too big and the model overshoots, too small and it learns slowly.
letterbox
Resizing a picture without changing its shape: the rest of the square is filled with grey, so nothing is stretched.
mAP@50
mAP where a box counts as correct if it overlaps the true box by at least 50% (IoU 0.5). The score our thesis targets.
mAP@50-95
A stricter mAP that averages the score over overlaps from 50% to 95%. It rewards tight, accurate boxes.
Market-1501
A public dataset of pedestrians. The original DeepSORT look-network was trained on pictures like these.
mosaic
An augmentation that pastes four pictures into one, so the model sees objects in new surroundings.
NMS
Non-Maximum Suppression: when several boxes cover the same object, keep the most confident one and drop the rest.
object detection
Finding every object of known kinds in a picture and drawing a box around each one.
OCR
Optical Character Recognition: reading the letters and digits in a picture.
ONNX
A standard file format (.onnx) that stores a trained model so many programs can run it without the training software.
optimizer
The method that decides how the model's numbers are changed after each batch.
precision
Of everything the model reported, the share that was correct. High precision means few false alarms.
Real-ESRGAN
A GAN-based super-resolution model that upscales pictures 4 times.
recall
Of everything that was really there, the share the model found. High recall means few misses.
ReID
Re-identification: deciding whether two pictures show the same car.
specialist model
A small model with one job, run only on the cropped part of the picture it needs (helmet, plate or cabin).
track ID
The steady number the tracker gives one vehicle for as long as it stays on screen.
transfer learning
Re-using what a model learned on one task (everyday objects) to learn a new task (helmets) with much less data.
Ultralytics
The company and Python library that provides YOLOv8 and the tools to train and export it.
VS Code
The code editor many developers use. The 'Open in VS Code' links jump straight to the line.
YOLO
'You Only Look Once'. A fast family of object detectors that find all objects in a single pass over the picture.
YOLOv8n
The smallest ('nano') model of YOLOv8: about 3 million adjustable numbers, fast enough for a normal laptop.
